Pre-Launch Security Guide

Secure Your
AI / Vibe-Coded App

Six practical checks for authentication, authorization, deployment, abuse protection, secrets, and AI-specific safety. This page is isolated from the main application and does not modify its authentication or data flow.

CHECK 01

🔐 Secure Authentication

Protect account creation and login against weak credentials, session abuse, and account takeover.

password hashingsession expiryemail verificationrate limiting
PROMPT 01
Act as a senior security engineer. Review the authentication system of this project and make it secure. Ensure passwords are securely hashed, sessions expire, email verification is enabled, password reset tokens expire, login attempts are rate limited, and authentication secrets are never exposed to the frontend. Refactor insecure authentication logic without changing the intended user experience.
CHECK 02

🛡️ Prevent Unauthorized Data Access

Users should only access resources they are authorized to access. Test every read, update, and delete path for IDOR and privilege escalation.

ownership checksAPI authorizationdatabase rulesRBAC
PROMPT 02
Review all API endpoints and database queries. Ensure every request verifies that the authenticated user owns or is authorized to access the resource. Prevent IDOR vulnerabilities and privilege escalation before reading, modifying, or deleting any resource.
CHECK 03

🚀 Secure Deployment & Monitoring

Production configuration should enforce HTTPS, protect secrets, restrict databases, and provide enough logging to investigate suspicious activity.

HTTPSsecret storageprivate DBsecurity logs
PROMPT 03
Audit the production deployment. Enforce HTTPS, verify that secrets are not committed to source control or shipped to the browser, restrict direct database access, configure safe logging, and identify suspicious authentication and API activity.
CHECK 04

🤖 Prevent Abuse & Bot Attacks

Protect login, signup, API, search, scraping, and AI-generation endpoints from automated abuse and unexpected cost spikes.

rate limitingbot protectionquotascraping controls
PROMPT 04
Add abuse protection to the application. Implement sensible rate limits and quotas for login, account creation, sensitive API endpoints, search, scraping-prone endpoints, and AI generation. Fail safely and do not expose internal implementation details in error responses.
CHECK 05

🔑 Protect Secrets & API Keys

Public client configuration can be visible. Private API keys, service-account credentials, signing secrets, and database credentials must never be shipped to the browser.

no secrets in frontendno secrets in repoenvironment variablesserver-side only
PROMPT 05
Scan the project for credentials, tokens, private keys, service-account JSON, database passwords, webhook secrets, and other sensitive values. Remove or rotate real secrets that are exposed. Keep only intentionally public client configuration in frontend code.
CHECK 06

🧠 Secure AI Features & Input Handling

AI endpoints need ordinary web security plus prompt-injection resistance, output validation, abuse limits, and protection against data leakage.

prompt injectionoutput validationPII leakagecost controls
PROMPT 06
Audit every AI feature for prompt injection, unsafe tool use, sensitive-data leakage, untrusted instructions, excessive token usage, and missing output validation. Ensure the model cannot bypass authorization, reveal secrets, execute unauthorized actions, or access another user's data.

Launch checklist

  • Authentication and email verification tested on a clean device.
  • Authorization tested with another user's UID/resource ID.
  • Firebase/database rules tested for anonymous and authenticated access.
  • Secrets scanned and rotated where exposure occurred.
  • Rate limits and abuse controls tested.
  • AI inputs, outputs, tools, and data boundaries reviewed.
